Torsion pretraining checkpoints and analysis
===========================================

Scope
-----
Four equivariant GNNs (HEGNN, TFN, MACE, Equiformer), seed 42, on the
same 86-molecule torsion cohort: 94 molecule--target pairs and 2,064
conformations. The fixed molecule split is 69 training / 17 validation.
The bundle contains four random initializations and eight validation-best
checkpoints: total-energy MAE pretraining and Uni-Mol-style pretraining.
These checkpoints were trained on torsion conformations, not other datasets.

The entry point is ``code/scripts/torsion_pretraining.py``; paired-score
analysis is implemented in ``code/utils/torsion_pretraining_analysis.py``.

Files and preparation
---------------------
Extract the three archives from the repository root::

    python -m zipfile -e checkpoints.zip .
    python -m zipfile -e datasets.zip .
    python -m zipfile -e source_data.zip .

The extracted layout separates weights, shared data and configuration::

    checkpoints/toy/{model}_{regime}.npz
    checkpoints/torsion/{model}_{variant}.pt
    datasets/torsion/trajectories/{record_id}.xyz
    datasets/torsion/responses.csv
    datasets/torsion/evaluated_pairs.json
    datasets/torsion/point_groups.csv
    configs/toy/{model}_{regime}.json
    configs/torsion_pretraining.json

The checkpoint directory contains only model files. The torsion variants are
``random``, ``energy`` and ``unimol``. Both training objectives read the same
``datasets/torsion`` inputs. The split is generated by sorting numeric record
IDs, applying a NumPy PCG64 permutation with seed 42, taking the first 17
molecules for validation and the remaining 69 for training. Energy statistics
use only the 1,656 training conformations (float64, population standard deviation).
To record the split and statistics without copying coordinates or labels::

    python code/scripts/prepare_torsion_data.py --out outputs/torsion_protocol

Training and analysis also generate these records in their output directories.
Point-group labels retain the original tolerance-0.1 and tolerance-0.3 assignments.

The trained checkpoint files contain ``backbone_config``,
``backbone_state_dict``, and ``model_state_dict`` (including the pretraining
heads). The tensor values are retained exactly. Distributed files contain model weights
and task heads; optimizer and RNG states are not included.
Each checkpoint is loadable with ``torch.load(..., weights_only=True)``.


Verify and reproduce tables (CPU)
--------------------------------
The supplied scores can be analyzed directly. Analysis requires NumPy, pandas,
SciPy and scikit-learn; it does not import PyTorch or require a GPU::

    python code/scripts/torsion_pretraining.py verify
    python code/scripts/torsion_pretraining.py analyze --scores source_data/torsion_pretraining/scores --out outputs/torsion_reproduced

The output directory must be empty. Main outputs:

* ``table_energy_extrema.csv``: peak/trough pLS changes, signed gap changes,
  fraction of molecules with increasing gaps, and all-extrema AUC changes.
* ``table_target_symmetry.csv``: target-present/absent pLS changes and
  fractions of molecules with increasing class gaps.
* ``table_special_angles.csv``: pLS changes at multiples of 90 degrees
  versus other angles, with paired molecule statistics.
* ``angle_energy_counts.csv``: local extrema counts at each sampled angle,
  counted once per conformation rather than once per target.
* ``{variant}_{model}/``: per-frame, per-pair and per-molecule results,
  angle-by-energy-type summaries, and bootstrap summaries.
* ``summary.json``: all/train/validation summaries and input checksums.

Recompute scores from checkpoints
--------------------------------
This requires the full project environment used by the four backbone models;
see ``code/environment.yml`` and the repository setup instructions. Use FP32 with
TF32 disabled, as enforced by the score-extraction script::

    python code/scripts/torsion_pretraining.py extract --model all --variant all --device cuda:0 --out outputs/torsion_scores
    python code/scripts/torsion_pretraining.py analyze --scores outputs/torsion_scores --out outputs/torsion_recomputed

A single model/variant can be selected, e.g. ``--model mace --variant unimol``.
CPU extraction is also supported. ``--limit 2`` is a quick extraction smoke;
partial score files are marked incomplete and rejected by the analyzer.
Existing score files are never silently overwritten.

Fresh FP32 inference may differ slightly across devices.

Definitions
-----------
Scores use degrees 0, 2, 4, 6 and epsilon 1e-10. Energy extrema are strict
periodic local extrema of the existing 15-degree scans. Retrieval sorts raw
pLS in descending order and averages exact ties. AUC is the area under the
recall--budget curve used for energy-extremum retrieval. Targets are averaged within
molecule, then molecules receive equal weight. Gap improvement counts use
1e-10 for peak--trough changes and 1e-6 for target-class and angular changes.
Raw pLS is used; no additional standard-deviation normalization is applied.
PointGroupAnalyzer labels at tolerance 0.1 include subgroup containment;
they are not mathematical certificates of exact symmetry.
A positive score-gap change does not necessarily imply higher retrieval AUC.

Uni-Mol-style pretraining is an adaptation to the four GNNs: masked atom
classification plus coordinate and pair-distance recovery, with loss weights
1, 5, 10. It retains the current all-atom torsion data and GNN architectures;
it is not a reproduction of Uni-Mol's original large-scale pretraining.
Both experiments select checkpoints by their own validation loss. Validation
molecules are excluded from gradient training but participate in selection.

Train from the paired initialization
------------------------------------
The two training scripts use the shared dataset and paired random
initializations by default. They write local CSV/JSONL logs, ``last.pt``
and validation-selected ``best.pt``. No online account is required::

    python code/scripts/train_torsion_energy.py --model hegnn --device cuda:0 --out outputs/energy_hegnn
    python code/scripts/train_torsion_unimol.py --model hegnn --device cuda:0 --out outputs/unimol_hegnn

Repeat with ``tfn``, ``mace`` and ``equiformer`` for all four architectures.
Use ``--device cpu --smoke`` and a fresh ``--out`` for a short check of
batching, rotations/reflections, gradients, checkpoint reload and spectra.
``--epochs 1`` runs one complete train/validation epoch. Production settings
are seed 42, batch size 8, AdamW (learning rate 3e-4, weight decay 1e-5),
gradient clipping at 5, at most 200 epochs and early stopping after 30
epochs without improvement. ReduceLROnPlateau uses factor 0.5, patience 9,
threshold 0 and minimum learning rate 1e-6.

The molecule split and energy normalization are generated deterministically;
only training molecules determine normalization and the random replacement vocabulary.
Uni-Mol-style coordinate/distance recovery uses the masked atoms, fixed
validation corruption, and loss weights 1/5/10. Distance targets use mean
6.312581655060595 and standard deviation 3.3899264663911888, as in the
original training protocol. Architecture, objective and checkpoint-selection
rules are unchanged by the portable data paths and local logging.

Resume a locally trained run by adding ``--resume`` to the same command,
including the same epoch budget and output directory. Distributed checkpoints
contain weights and task heads only; they cannot resume the original optimizer
trajectory. New local ``last.pt``/``best.pt`` files also retain optimizer,
scheduler and RNG states. Only load such full training states from trusted
local runs. The supplied weights use the restricted ``weights_only=True``
loader. The original trained weights are provided unchanged; reproducing their
exact floating-point values on different hardware is not guaranteed.

Distribution
------------
``archives.json`` lists archive and extracted-file checksums. The root
``files.json`` covers the archives, code, configuration, demos and
documentation. ``configs/torsion_pretraining.json`` verifies the 12 checkpoints
and shared torsion inputs after extraction, together with the supplied scores. Dataset provenance
and distribution terms are described in ``DATASETS.md`` and ``THIRD_PARTY_NOTICES.md``.
